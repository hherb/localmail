## Project context (1-minute version)

`localmail` mirrors IMAP accounts (Gmail OAuth, password) into Postgres,
**strictly read-only w.r.t. IMAP**. The **database is canonical for accounts**
end-to-end. The daemon hot-reloads its account set (2B.1), records per-thread
heartbeats (2B.2), consumes a DB command queue with LISTEN/NOTIFY wake (2B.3),
is supervised + controllable via two planes (2B.4), and has non-blocking
lifecycle control + an admin panel (2B.5). Downstream consumers read the DB +
attachment tree directly or via the `localmail serve` HTTPS API. See
[CLAUDE.md](CLAUDE.md), [README.md](README.md), and the 2B respec
[docs/superpowers/specs/2026-05-30-daemon-control-2b-respec-design.md](docs/superpowers/specs/2026-05-30-daemon-control-2b-respec-design.md).

## What we shipped this session

### #148 — daemon panel surfaces rejected controls as a toast

- New served static
  [src/localmail/serve/admin/static/daemon-panel.js](src/localmail/serve/admin/static/daemon-panel.js)
  binds a `document.body` `htmx:afterRequest` listener, **filtered to
  `requestConfig.verb === "post"`** so the periodic GET status poll doesn't
  toast on every tick. On a POST result it renders a transient toast
  (`TOAST_TTL_MS = 6000`) in `#daemon-toast`: 409 → "another op in progress",
  400 → "rejected (invalid/expired session)", other non-2xx → generic
  `HTTP <n>`, 2xx → "Request accepted." Status codes are named constants
  (`STATUS_BUSY = 409`, `STATUS_CSRF = 400`) — no magic numbers.
- The `#daemon-toast` region lives in
  [daemon/panel.html](src/localmail/serve/admin/templates/daemon/panel.html)
  **outside** the self-swapping `#daemon-status` fragment, so the 2s `outerHTML`
  poll can't wipe an in-flight message. Pinned by
  `test_toast_region_lives_outside_polling_partial`.
- **Why a served file, not inline / not `hx-on::`:** the `/admin` CSP is
  `script-src 'self'` with **no `unsafe-inline`/`unsafe-eval`**, so an inline
  `<script>` or an htmx `hx-on::after-request` handler would be CSP-blocked.
- `/v1/admin/*` stays **pure machine-JSON** — feedback is derived client-side
  from the HTTP status, never a negotiated HTML body.
- `.daemon-toast` styles (error/ok kinds) appended to `admin.css`.

### #149 — close() can't orphan a child re-spawned mid async-restart

- [src/localmail/serve/daemon_supervisor.py](src/localmail/serve/daemon_supervisor.py):
  `close()` sets a new `_closing` flag **under `_lock` before** its blocking
  `stop()`; `start()` checks `_closing` under `_lock` as the **single spawn
  chokepoint** and no-ops when closing. The flag-set and the spawn are
  serialised by `_lock`: `start()` either sees the flag and skips, or it spawned
  first and `close()`'s `stop()` reaps it. Guarding `start()` also neutralises
  any `request_*` issued after `close()`.
- Test (`test_close_during_async_restart_does_not_respawn`) lands `close()`
  **deterministically** in the `stop()`→`start()` gap via a `_BarrierRestartSupervisor`
  subclass whose `restart()` pauses between halves on a `threading.Event`;
  `close()` uses the real (non-blocking) `stop()`. Plus
  `test_start_after_close_is_a_noop` for the flag in isolation.

## Open decisions & risks

1. **#148 toast is client-side by necessity.** `/v1/admin/*` must stay pure
   machine-JSON (CLAUDE.md + `tests/test_session_cookie_scope.py`), so error
   feedback is derived from the HTTP status in `daemon-panel.js` — there is **no
   server-side render of the toast**, hence no server-side test of it. The
   TestClient tests assert the **wiring** (region present, region *outside* the
   swapped partial, JS served & references the statuses). Don't "fix" this by
   negotiating HTML into the machine routes.
2. **The toast region must stay outside `#daemon-status`.** It's in `panel.html`,
   not `_status.html`, so the 2s `outerHTML` poll can't wipe an in-flight
   message. `test_toast_region_lives_outside_polling_partial` enforces it — keep
   it green.
3. **`#149` flag is one-way and terminal.** `close()` sets `_closing = True`
   permanently; `start()` is inert afterward. That is correct for serve-shutdown
   teardown — a `DaemonSupervisor` is **not** meant to be reused after `close()`.
   `test_start_after_close_is_a_noop` pins this. Don't add a "reopen" path
   without a real requirement.
4. **`#149` correctness rests on `_lock` serialising flag-set vs spawn.**
   `start()` holds `_lock` across its whole spawn decision (the `Popen` is inside
   `with self._lock`), and `close()` takes `_lock` to set the flag. Don't move
   the `Popen` outside the lock or set the flag outside it — that reintroduces
   the race.
5. **Migration numbering** — latest applied is **0024** (daemon_commands). This
   session added **no** migration. Next free slot: `0025_*.sql`. Re-check
   `ls migrations/` at plan-time.
6. **No ROADMAP.md** in this repo *(carried)* — slice status lives in
   NEXT_SESSION/handoffs + the specs. The `/nextsession` ROADMAP step is a no-op
   here by design.
7. **Heartbeat vocabulary still load-bearing** *(carried)* — any new heartbeat
   call site must use a `worker_kind`/`state` present in both the SQL CHECK lists
   (0023) and the `WorkerKind`/`WorkerState` Literals; all loop heartbeats go
   through `safe_heartbeat`.
8. **Tooling note** *(carried)* — the full-suite run emits harmless psycopg pool
   `__del__` ResourceWarnings at interpreter teardown — *not* a failure
   (`1222 passed`).
9. **`.claude/` local files** stay untracked, by design.
