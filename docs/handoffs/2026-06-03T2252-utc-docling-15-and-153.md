## Project context (1-minute version)

`localmail` mirrors IMAP accounts (Gmail OAuth, password) into Postgres,
**strictly read-only w.r.t. IMAP**. The **database is canonical for accounts**
end-to-end. The daemon hot-reloads its account set (2B.1), records per-thread
heartbeats (2B.2), consumes a DB command queue with LISTEN/NOTIFY wake (2B.3),
is supervised + controllable via two planes (2B.4), and has non-blocking
lifecycle control + an admin panel (2B.5). **The 2B arc is complete.** Hybrid
search (Phases 1+2) + an HTTPS GUI server are shipped. A Tauri + Svelte GUI
lives under `gui/`. See [CLAUDE.md](CLAUDE.md), [README.md](README.md).

### 2. #153 — cap consecutive transient docling re-attempts (PR #156, branch `fix-153-cap-transient-retries`)

#47 routed docling third-party network errors through the *transient* path
(ROLLBACK + WARNING, no `failed_extractions` row, `retry_count` untouched), so
a *permanently* failing error (HF 401/403, 404 for a removed model) re-attempted
**every sweep forever**. The fix:

- **Migration 0025 — `transient_extractions`** counter table, keyed on
  `sha256`, **deliberately independent of `failed_extractions.retry_count`**
  (which stays reserved for poison-pill semantics).
- **`config.py`**: new `extract_worker_max_transient_retries: int = 5` (larger
  than the poison cap of 3 since transients are often recoverable, but now
  bounded).
- **`extract_worker.py`**:
  - pure `transient_budget_exhausted(count, cap)` (`count >= cap`) matching the
    SQL `transient_count < cap` filter;
  - `_record_transient` / `_record_transient_safely` (nested SAVEPOINT, mirrors
    `_record_failure_safely`) bump the counter and return the new count;
  - `_claim_batch` LEFT JOINs `transient_extractions` and excludes blobs at the
    cap; returns the prior `transient_count` as a **5th column** so the reset
    DELETE is skipped on the common no-history path;
  - `_clear_transient` resets on a successful extraction (so the cap counts
    **consecutive** failures);
  - at the cap, one distinct **"giving up" WARNING** replaces the per-sweep
    retry line.
- **`cli.py`**: `retry-failed-extractions` now clears **both**
  `failed_extractions` and `transient_extractions` rows (per-blob with
  `--sha256`, else all) — the recovery path for a stuck-transient blob.
- **Docs**: CLAUDE.md (#153 note rewritten resolved, table list, migration
  numbers → 0025/next 0026) + README (transient section, command table).

1. **Both PRs green; no shared files** — `deps-docling-2.94-security` touches
   only `pyproject.toml` + `uv.lock`; `fix-153-cap-transient-retries` touches
   the worker/migration/CLI/tests/docs. Merge in either order, no rebase needed.
   CI runs `uv sync --frozen` (no extraction extra) so docling-dependent paths
   skip there — same as every prior session.
2. **#153 design note — why a separate table, not a `retry_count` bump.** The
   transient path must NOT touch `failed_extractions.retry_count` (that's the
   poison-pill cap, semantically distinct). The new `transient_extractions`
   counter is the independent state the issue called for. When the cap is hit
   the blob has **no `attachment_text` and no `failed_extractions` row** — it's
   surfaced by the single "giving up" WARNING + the `transient_extractions`
   table itself (not silent); recovery is `retry-failed-extractions` (now
   clears both tables). If a future session wants stuck-transient blobs in
   `list-failed-extractions` output, that's a deliberate, additive follow-up —
   don't poison-pill them (it would muddy `retry_count`).
3. **`extract_worker.py` is now 652 lines** (was 531 before this change, already
   over the 500-line guideline). It's one cohesive worker. A reasonable
   follow-up refactor: extract the failure/transient **persistence** helpers
   (`_record_failure{,_safely}`, `_record_transient{,_safely}`,
   `_clear_transient`, `_record_failure`) into an `extract_state.py` module
   (~140 lines) — would bring the worker back toward ~510 and group the
   SAVEPOINT-disciplined DB writes. Not done this session to keep the bugfix
   diff focused; no behaviour change implied.
4. **docling 2.20 → 2.97 is a wide jump** but it only affects the optional
